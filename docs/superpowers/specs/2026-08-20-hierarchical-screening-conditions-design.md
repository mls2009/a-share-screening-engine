# 分层筛选条件设计

## 目标

把平铺的指标列表改为业务语义明确的分层选择，严格区分上涨/下跌和放量/缩量，并让板块、上市阶段、K 线形态等枚举条件支持多选。

## 交互

每个条件行按“分类 → 条件 → 周期/选项 → 比较方式”逐级展开，不再一次展示所有指标。分类包括价格行情、成交活跃度、技术指标、股票属性、交易状态、K 线形态、趋势与点位。

- 上涨幅度和下跌幅度使用正数输入。下跌条件在生成 API 条件时翻转比较符和数值，例如“下跌幅度 ≥ 30%”转换为 `return_n <= -30`。
- 成交量增加/减少使用相同的正数幅度语义。
- 板块和 K 线形态支持多选，同一条件内任一选项命中即成立。
- 上市阶段支持新股（0–30 交易日）、次新股（31–250 交易日）和老股（超过 250 交易日）多选。
- 停牌和 ST 使用业务文案，不向用户暴露 `true/false`。
- 同一条件内多选为 OR；条件之间仍使用现有 AND/OR/NOT 树。

## 数据契约

`/api/catalog` 为每个指标返回分类、条件族、周期、方向和枚举选项。原始指标 key 仍是后端评估的唯一事实源，前端只负责把友好语义转换成现有条件。

枚举多选通过 `in` / `not_in` 操作符传输。`listing_stage` 由 `listing_trade_days` 动态派生，无需重新同步历史行情。

## 验收标准

1. 界面不再出现含糊的“涨跌幅”条件，只显示上涨幅度和下跌幅度。
2. 下跌 30% 输入为正数 30，产生 `return_n <= -30`。
3. 板块、上市阶段和 K 线形态可多选，后端能正确评估包含/不包含。
4. 停牌和 ST 显示可读业务选项。
5. 筛选页和回测页共用的条件树仍能构建、验证和提交。
