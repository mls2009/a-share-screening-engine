# A 股全市场真实数据与筛选引擎设计

## 1. 目标

建立可断点续传的全市场 A 股真实数据库，并提供可复现、可解释的选股引擎。
引擎支持日线、周线、月线特征，可在盘中叠加实时行情，并支持任意层级的
`AND / OR / NOT` 条件树。

本规格是三个依赖阶段中的第一阶段：

1. 全市场真实数据与筛选引擎（本规格）。
2. 任意嵌套条件的前端编辑器。
3. 专业 K 线图、自动支撑/压力展示与手动画线。

第一阶段必须提供稳定的内部 API 和命令行入口，后两个阶段直接复用，
不重写筛选逻辑或数据读取。

## 2. 已有基础与当前状态

项目已具备：

- DuckDB 迁移与元数据表。
- Parquet K 线存储和数据覆盖区间。
- BaoStock 历史数据和基础资料适配器。
- mootdx 实时行情与腾讯实时备用源。
- 5/15/30/60 分钟、日、周、月周期领域模型与聚合能力。

但当前仓库中没有已生成的 `data/astock.duckdb` 或 K 线 Parquet 数据文件。
因此当前是“有数据库结构与读写能力，尚未建立全市场实盘数据”，不能把
模拟数据当成真实选股结果。

## 3. 范围与非目标

### 3.1 本阶段范围

- 全部在市沪、深、北 A 股，不默认排除 ST、停牌、新股或次新股。
- 首次优先同步最近 3 年真实前复权日线，之后可后台逐步补齐更早历史。
- 每日收盘后增量同步，不重复下载已覆盖区间。
- 日线特征，以及由日线聚合的周线、月线特征。
- 收盘模式和盘中模式。
- 行情、技术面、K 线形态、股票属性、自动支撑/压力特征。
- 命令行入口和内部 HTTP API。
- 条件命中解释、排名、分页、执行记录与数据新鲜度。

### 3.2 本阶段非目标

- 不实现正式的前端条件编辑器。
- 不实现专业 K 线图和手动画线 UI。
- 不将分钟 K 线用于全市场扫描；分钟 K 线仍供单股图表和监控使用。
- 不引入财务报表、行业概念、龙虎榜或融资融券等新数据源。
- 不允许执行用户输入的任意 Python、SQL 或数学表达式。

## 4. 总体架构

```text
BaoStock 全市场股票列表与日线
        |
        v
数据同步服务
        |-- 原始前复权日线 ----------> Parquet
        |-- 股票属性/交易日历 -------> DuckDB
        `-- 日/周/月常用特征 ---------> DuckDB
                                             |
腾讯实时行情 --> 盘中临时特征 ------+
                                             v
                                      条件树筛选引擎
                                             |
                                             v
                                      排名/解释/分页
```

原始 K 线、可查询特征和筛选运行记录分层存储。筛选引擎不依赖供应商字段，
只依赖归一化后的 K 线、实时快照、特征和股票属性。

## 5. 数据与存储设计

### 5.1 Parquet K 线

- 保存真实前复权日线 OHLC、成交量、成交额、数据源和完成状态。
- 物理保存日线；周线和月线由日线按实际交易日聚合。
- 利用现有 `bar_coverage` 记录每只股票的覆盖区间，支持缺口补齐。
- 质量检查失败的 K 线不进入特征仓库。

### 5.2 DuckDB 表

#### `symbols`

扩展现有股票表，保存：

- 代码、名称、交易所、板块。
- 上市日、退市日、当前是否在市。
- 最新 ST、停牌和可交易状态。

#### `market_features`

按 `symbol + timeframe + feature_date + feature_version` 保存日/周/月高频使用的
宽表特征。周线和月线记录使用该周期最后一个实际交易日作为 `feature_date`：

- 价格、涨跌幅、高低点位置。
- 成交量、成交额、均量、量价状态。
- MA、MACD、KDJ、RSI、布林线、ATR、OBV。
- 振幅、波动率、最大回撤和连续状态。
- 上市交易日数、新股/次新股状态。
- 实时市值、换手率、量比等只有快照口径的字段不伪造历史值；
  收盘模式仅在有可追溯数据时提供这些条件。

#### `pattern_events`

按股票、周期、日期和形态类型保存：

- 是否命中、强度分数。
- 实体、上影线、下影线和振幅比例。
- 所使用的确定性规则和阈值。
- 用于图表定位的发生日期。

#### `support_resistance_zones`

保存自动识别的价格区域和趋势通道：

- 支撑/压力、水平/趋势、日/周/月周期。
- 计算截止日、中心价、上下边界。
- 趋势通道的斜率、截距和有效锨点。
- 强度、触碰次数、首次/最近触碰日期。
- 突破、跌破、回踩和角色转换状态。
- 计算规则版本。

#### `data_sync_jobs`

记录同步范围、开始/结束时间、当前状态、总数、成功数、失败数、当前代码、
失败原因和可恢复位置。

#### `screen_definitions`

保存筛选器名称、条件树 JSON、版本、创建/修改时间。

#### `screen_runs`

保存执行时间、收盘/盘中模式、数据截止日、特征版本、条件树快照、
股票池规模、实时覆盖数、失败数和运行状态。

#### `screen_matches`

保存入选股票、排名、展示特征快照、每个条件的实际值、比较值、真假结果和
完整布尔计算路径。盘中运行的实时快照与结果一起保存，便于事后解释。

### 5.3 手动画线合同

手动画线在第三阶段实现，但本阶段明确其合同：

- 手动线属于某一只股票和某一周期。
- 类型为支撑或压力，几何形式为水平区域或趋势通道。
- 保存锨点、延伸方向、区域宽度、创建时间和锁定状态。
- 手动线只用于对应股票、自选股和监控，不把单股画线错用到全市场。

## 6. 数据同步与恢复

### 6.1 首次建库

1. 获取全部在市 A 股与上市信息。
2. 为每只股票计算最近 3 年内的缓存缺口。
3. 按供应商可承受的速率逐只下载前复权日线。
4. 每只股票通过质量检查后立即写入 Parquet 并记录覆盖区间。
5. 为同步完成的股票构建日、周、月特征。
6. 失败股票记录原因并继续，不因单只失败回滚全部建库。

### 6.2 断点续传

- 中断后根据 `bar_coverage` 和 `data_sync_jobs` 只补缺失范围。
- 可单独重试失败股票。
- 日线补齐后仅重算受新数据影响的指标尾部窗口。
- 同步状态始终显示数据截止日和最后成功时间。

### 6.3 收盘与盘中模式

#### 收盘模式

- 只使用已完成 K 线。
- 不用本机当前价覆盖最新收盘价。
- 同一数据版本与条件树可重复得到相同结果。

#### 盘中模式

- 按批获取全市场实时价格、成交量和成交额。
- 在内存中把快照叠加到已完成日线，用于盘中涨幅、放量、突破等特征。
- 盘中临时 K 线不写入已完成历史日线。
- 保存本次快照、覆盖率和失败批次，不把缺失行情当作零值。

## 7. 特征目录

### 7.1 涨跌与收益

- 1/3/5/10/20/60/120/250 个交易日涨跌幅。
- 周、月、年内涨跌幅。
- 连续上涨/下跌天数。
- 涨停/跌停次数。
- 指定窗口最大回撤和最大单日涨跌幅。

### 7.2 价格与位置

- 最新价、价格区间、振幅中的收盘位置。
- 距 N 日高点/低点的百分比。
- 创 N 日新高/新低。
- 突破前高/前低、跳空高开/低开。

### 7.3 成交量与成交额

- 当日成交量/额与 N 日均值。
- 放量/缩量倍数，连续放量/缩量。
- 价涨量增、价涨量缩、价跌量增、量价背离。
- 量比、换手率和实时成交额（有可追溯快照时）。

### 7.4 趋势和技术指标

- MA5/10/20/30/60/120/250。
- 均线多头/空头排列、上穿/下穿、斜率和乖离率。
- MACD、KDJ、RSI、布林线、ATR、OBV。
- 金叉、死叉、超买、超卖和可确定计算的背离状态。

### 7.5 波动

- 日振幅、历史波动率、ATR 百分比。
- 连续窄幅、波动放大和整理区间收窄。

### 7.6 股票属性

- 沪/深/北，主板/创业板/科创板/北交所。
- ST、停牌、上市交易日数、价格、市值。
- 新股：上市不超过 30 个交易日。
- 次新股：上市第 31–250 个交易日。
- 新股/次新股阈值在后续前端中可调整，默认使用上述口径。

## 8. K 线形态

K 线形态是可解释的确定性特征，不使用不可复现的 AI 判断。

### 8.1 默认形态

- 阳线、阴线、十字星、长上影、长下影、锤头。
- 看涨/看跌吞没、刺透、乌云盖顶。
- 早晨之星、黄昏之星、三连阳、三连阴。
- 突破整理区间。

例如，十字星默认要求实体长度不超过整根 K 线振幅的 10%；锤头线默认要求
下影线不小于实体的 2 倍且上影线较短。具体阈值是有版本的规则，
不在不同执行间静默变化。

### 8.2 可筛选形式

- 当前是否出现。
- 最近 N 个交易周期内是否出现。
- 最近 N 个周期出现次数。
- 形态强度分数。
- 实体/影线/振幅比例。

普通模式使用系统默认阈值；高级模式允许在受控范围内调整实体比例、影线倍数、
回看周期和最低强度。

## 9. 支撑位与压力位

所有支撑和压力都表示为价格区域或趋势通道，不将其伪装成绝对精确的单一价格。

### 9.1 自动水平区域

- 从有效波峰、波谷、平台密集成交区和跳空缺口提取候选价格。
- 使用 ATR 和价格百分比作为容差，合并相近价格为区域。
- 根据触碰次数、时间跨度、成交量反应、反弹/回落幅度和最近有效日期评分。
- 压力突破后可转为候选支撑；支撑跌破后可转为候选压力，但必须标记角色转换。

### 9.2 自动趋势通道

- 从至少两个有效波谷拟合趋势支撑，从至少两个有效波峰拟合趋势压力。
- 根据第三次及后续触碰、时间跨度、斜率稳定性、ATR 偏差和假突破次数评分。
- 趋势线带有上下容差，每个交易日都能计算当日对应的价格范围。

### 9.3 可筛选条件

- 距离最近水平支撑/压力的百分比。
- 距离下一压力区的上涨空间。
- 支撑/压力强度和触碰次数。
- 放量突破、跌破、突破后回踩不破。
- 接近上升趋势支撑或下降趋势压力。
- 周线压力被日线收盘突破。
- 支撑与压力区间收窄。

### 9.4 后续 K 线图合同

- 支撑统一为绿色，压力统一为红色。
- 自动区域/趋势通道使用虚线、半透明色带和“自动”标签。
- 手动区域/趋势通道使用实线和“手动”标签。
- 不仅依赖红绿颜色，同时使用虚线/实线、标签和图标区分来源。
- 默认显示离现价最近的 3 组支撑和 3 组压力，可展开全部。
- 默认显示当前 K 线周期，可选叠加周线、月线等更高周期区域。
- 手动画线前选择支撑或压力，系统自动使用对应颜色。
- 水平区域可调整上下边界，趋势通道可调整锨点和通道宽度。

## 10. 条件树与比较语义

### 10.1 受控抽象语法树

条件树只包含：

```text
Group(operator=AND | OR | NOT, children=[...])
Condition(
  metric,
  timeframe,
  lookback,
  comparator,
  operand,
  multiplier,
  unit
)
```

`NOT` 只接受一个子节点；`AND` 和 `OR` 至少接受两个子节点。编辑器不施加
“只能一层”之类逻辑限制，条件可任意组合嵌套。为防止异常请求耗尽本地资源，
API 安全上限为 32 层和 512 个节点，这不改变正常使用中的任意嵌套语义。

### 10.2 操作数

右侧操作数支持：

- 固定数值。
- 另一个指标字段。
- 另一个指标字段乘以一个倍数。

例如：

```text
20日涨幅 > 30%
今日成交量 > 20日均量 * 2
MA5 > MA20
实时价 > 昨日最高价
```

### 10.3 比较符

- `>`、`>=`、`<`、`<=`、`=`、`!=`。
- 位于区间/不在区间。
- 上穿/下穿。
- 连续满足 N 个周期。
- N 个周期内至少满足 M 次。

百分比、元、股、万元、亿元、倍数和交易日等单位在特征注册表中显式定义。
不兼容的字段和单位在执行前拒绝。

### 10.4 编译与安全

- 指标字段必须存在于有版本的白名单注册表。
- 比较符映射到固定语义，不接收任意操作符字符串。
- 条件树编译为参数化 DuckDB SQL，不直接拼接用户文本。
- 不使用 `eval`，不执行用户 Python 或 SQL。

## 11. 筛选执行与解释

1. 校验条件树结构、字段、周期、单位和操作数。
2. 确定全部在市 A 股宇宙。
3. 选择指定数据日和特征版本。
4. 盘中模式获取实时快照并构建临时特征。
5. 将条件树编译为参数化 SQL，由 DuckDB 一次向量化执行。
6. 为入选股票计算每个叶子条件和组节点的实际结果。
7. 排序、分页并保存运行与结果快照。

数据不足、停牌、指标预热不足和实时快照缺失均是显式状态，不隐式转换为零。
默认三值语义为 `true / false / unavailable`；只有整棵树明确计算为 `true` 才入选，
不可用数据的原因进入运行统计和诊断结果。

## 12. 性能设计

- 常用指标按日预计算，收盘筛选不逐只读取 Parquet。
- 开放的条件数量与任意嵌套层级由 AST 统一编译，不转化为 Python 逐股循环。
- K 线形态的默认规则预计算；高级自定义阈值在请求时计算受控窗口。
- 全市场实时行情分批请求，批次大小受 URL 长度和供应商稳定性约束。
- 失败批次单独重试，并报告覆盖率。
- 特征就绪后，全市场收盘筛选的目标是通常在 5 秒内完成；
  盘中模式的主要耗时是外部实时行情请求。

## 13. 命令行与内部 API

### 13.1 命令行

```bash
# 首次建库，默认最近 3 年
astock data sync-market --years 3

# 查看进度与失败股票
astock data status

# 重试上次失败部分
astock data retry-failed

# 收盘模式
astock screen run monthly-volume-breakout --mode close

# 盘中模式
astock screen run monthly-volume-breakout --mode live

# 查看结果和命中解释
astock screen results <run-id>
```

### 13.2 内部 API

```text
POST /api/screens/validate       校验条件树、字段和单位
POST /api/screens/run            执行收盘或盘中筛选
GET  /api/screens/{run_id}       返回结果、排名、解释和新鲜度
GET  /api/features/catalog       返回前端下拉框所需的字段、单位和操作符
GET  /api/symbols/{symbol}/bars  返回真实 K 线和形态事件
GET  /api/symbols/{symbol}/zones 返回自动支撑/压力区域和趋势通道
GET  /api/data/status            返回同步进度、失败数和数据新鲜度
```

K 线 API 保留 5/15/30/60 分钟、日、周、月周期合同；全市场筛选只使用日/周/月
特征和实时快照。

## 14. 结果展示合同

每只入选股票至少返回：

- 代码、名称、交易所、板块。
- 数据日期、最新价、涨跌幅。
- 成交量/成交额变化、换手率、市值（有可用快照时）。
- 上市交易日数、新股/次新股状态。
- 排名值。
- 每个条件的字段、周期、实际值、比较值、单位和真假结果。
- 完整 `AND / OR / NOT` 计算路径。
- 数据不可用的诊断统计。

后续前端不需要重新解释条件逻辑，只渲染 API 返回的结构化解释。

## 15. 错误处理

- 无效条件树：返回精确节点路径和错误原因。
- 字段/周期/单位不匹配：执行前拒绝。
- 数据同步失败：记录到作业和股票级错误，其他股票继续。
- 特征版本不兼容：不复用旧结果，要求重建受影响特征。
- 实时源部分失败：保存覆盖率，不把缺失数据当零。
- 结果过期：继续可查看，但明确标记数据截止时间。

## 16. 测试与验收

### 16.1 单元测试

- 日/周/月特征计算。
- 新股 0–30 和次新股 31–250 交易日边界。
- 固定数值、字段比较和字段乘倍数。
- 任意嵌套 `AND / OR / NOT` 和三值语义。
- 单位不匹配拒绝。
- K 线形态规则和强度。
- 水平支撑/压力聚类、趋势通道、角色转换。
- 任一历史截止日的计算只读取当日及以前数据。

### 16.2 集成测试

- 小型固定股票池从同步、特征构建到筛选结果。
- 中断同步后只补缺口。
- 收盘模式重复执行结果一致。
- 盘中快照叠加不污染历史 K 线。
- 筛选运行和完整条件解释可持久化。
- K 线、特征目录、支撑/压力 API 合同。
