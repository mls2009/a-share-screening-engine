# ETF 同步与证券搜索设计

## 目标

将沪深交易所上市 ETF 纳入现有行情同步链路，并让 K 线研究页支持六位代码和中文名称模糊搜索。股票的现有行为保持不变。

## 范围

- 支持上海、深圳上市 ETF，不将债券、LOF 或其他基金类型自动纳入。
- ETF 使用现有 BaoStock 参考数据和历史 K 线链路。
- ETF 与股票一样同步前复权日线和 5 分钟数据；15/30/60 分钟、周线、月线继续由现有聚合逻辑生成。
- ETF 进入现有 K 线、成交量、支撑压力、回测和实时监控链路。
- 本次只修改 K 线研究页的证券搜索交互，不改造回测和监控页的输入框。

## 数据模型与同步

`symbols` 表和 `Security` 模型新增 `instrument_type`，取值为 `stock` 或 `etf`，旧数据默认为 `stock`。

BaoStock 证券目录仍排除不支持的其他证券类型，但对符合沪深 ETF 代码规则的证券设置 `instrument_type=etf` 并保留。市场同步不再只生成股票任务，而是对所有在市的 `stock` 和 `etf` 使用同一历史行情流程。

ETF 代码识别集中在一个可测试的函数内，避免在同步、API 和前端各自复制判断。

## 搜索 API

新增只读接口 `GET /api/symbols/search?q=<query>&limit=<n>`，仅查询本地 `symbols` 表中在市的股票和 ETF。

- 六位数字代码可命中完整带交易所后缀的证券。
- 带 `.SH` / `.SZ` 的代码支持精确匹配。
- 中文输入按名称包含关系模糊匹配。
- 代码精确匹配优先，其次是代码前缀，再其次是名称匹配；结果数量受 `limit` 限制。
- 返回 `symbol`、`name`、`exchange` 和 `instrument_type`。

API 不为本地未同步的证券即时联网，搜索结果与本地可用 K 线数据保持一致。

## K 线搜索交互

用户输入代码或中文名称时，前端调用搜索 API 显示下拉候选项，每项显示“名称、完整代码、股票/ETF”。点击候选项后使用其完整代码读取 K 线。

用户输入六位代码并直接提交时，前端先使用搜索结果解析成完整代码；无匹配时显示明确提示，不用错误的缺后缀代码请求 K 线。

## 失败处理

- 搜索输入为空时返回空结果。
- ETF 同步失败沿用现有逐证券同步任务的失败记录和重试机制。
- 搜索请求失败时，前端显示错误，不改变当前已打开证券。
- 不在搜索过程中触发全市场同步。

## 验证

- 数据源测试：ETF 被保留并标记为 `etf`，LOF/债券仍被排除，股票仍标记为 `stock`。
- 迁移测试：旧 `symbols` 表增加非空类型列且旧行默认为股票。
- API 测试：`159558`、`159558.SZ` 和中文名称片段都能返回 ETF，排序和数量限制稳定。
- 前端测试：中文输入显示候选项，六位代码可打开完整证券代码，无匹配不会破坏当前图表。
- 回归测试：现有 Python 、前端测试、生产构建和 K 线端到端测试通过。
