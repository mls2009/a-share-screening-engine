# 自动线悬停数值与方向趋势线设计

## 目标

K 线图上的自动支撑、压力和趋势线平时只显示线条，不在线尾常驻显示名称或价格。鼠标移到线上时才显示该位置的具体数值。

自动趋势线不再被强制定义为支撑或压力，而是按方向分为上升趋势线和下降趋势线。每个周期最多同时显示最优上升线一条和最优下降线一条；只有一个方向成立时只显示该方向，不人工补齐。

## 范围

- 适用于 `5m`、`15m`、`30m`、`60m`、日线、周线和月线。
- 每个周期使用该周期自己的 K 线和拐点独立计算，不共用其他周期的斜率。
- 水平支撑和水平压力的计算、支撑压力转换、删除及删除后重现虚线规则保持不变。
- 手动画线仍保留用户选择的“支撑/压力”语义、颜色、常驻标签和删除能力。“不再区分支撑/压力”只适用于自动趋势线。
- 下方线条列表仍显示名称、当前价格、触及次数和删除按钮。

## 根因与架构决策

当前图表 API 调用 `nearest_zones()`，所有几何类型都按 `support/resistance` 分组并共享返回限额。更靠近现价的水平线会把趋势线挤出 API 结果。同时，现有日线算法会为了凑齐“趋势支撑+趋势压力”而平移拟合线，与新的方向语义不一致。

采用图表专用选择路径：

1. `nearest_zones()` 只为选股特征返回最近的水平支撑和水平压力，避免方向趋势线改变现有筛选指标。
2. 图表 API 使用独立的图表线选择函数，返回最近水平支撑/压力、所有当前手动线，以及最优上升/下降自动趋势线。
3. 自动趋势线使用 `zone_kind=uptrend` 或 `zone_kind=downtrend` 持久化；手动趋势线仍使用 `support/resistance`。不新增数据表或字段。

## 趋势线识别

1. 从该周期最近的高点和低点拐点生成连续窗口候选，每个候选至少包含两个锚点。
2. 对候选锚点做最小二乘直线拟合。平均残差不得超过该周期基于 ATR 的价格容差。
3. 候选在首尾锚点之间的总变动必须至少达到一个价格容差，用于排除近似水平的“伪趋势线”。
4. 斜率大于零的候选归为上升趋势，斜率小于零的候选归为下降趋势。
5. 每个方向按最后锚点越近、触及数越多、归一化残差越小的顺序排名，只保留第一名。
6. 不根据趋势线当前位于收盘价上方或下方来改名，也不为缺失方向生成人工平移线。

## 图表交互

- 自动水平支撑使用绿色，自动水平压力使用红色。
- 自动上升趋势线使用绿色，自动下降趋势线使用红色；悬停文案明确写“上升趋势线”或“下降趋势线”，不写支撑/压力。
- 自动线关闭常驻 `markLine.label` 和趋势线 `endLabel`。
- 自动水平线悬停提示包含线条名称和固定中心价。
- 自动趋势线悬停提示包含方向名称、鼠标所在 K 线日期/时间及该时刻的拟合价。
- 只有鼠标命中自动线条时才显示该提示，不把所有自动线数值混入 K 线的轴向提示。
- 删除后重现的自动线仍使用虚线，其他线使用实线。
- 自动线删除、手动线绘制和图表缩放操作保持可用。

## 数据流

1. 特征构建器从指定周期 K 线检测水平区域和方向趋势线，按原有批次逻辑替换该周期的自动结果。
2. K 线页面请求图表线 API，后端分别选择水平支撑/压力与方向趋势线，再合并手动线。
3. 前端根据 `geometry`、`zone_kind`、`source` 和 `reappeared` 生成线型与悬停提示。
4. 切换周期后重新请求该周期 K 线和图表线，不复用上一周期的趋势结果。

## 异常与边界

- 拐点不足或没有通过残差/总变动条件的候选时，该方向不显示趋势线。
- 锚点日期不在当前图表 K 线窗口中且无法映射出两个点时，该趋势线不渲染，避免画出错误斜率。
- 自动线删除失败时保持现有线条和错误提示，不伪装成删除成功。
- 自动叠加线不因悬停交互而影响 K 线和成交量提示。

## 验收标准

1. 构造同时含有上升和下降拐点的数据时，同一周期返回且只返回一条 `uptrend` 和一条 `downtrend` 自动线。
2. 只有上升候选时不生成下降线，反之亦然。
3. 近似水平的候选不被当作趋势线。
4. 图表 API 中的水平线限额不会挤掉上升/下降趋势线；选股特征仍只使用水平支撑和压力。
5. 自动水平线和自动趋势线无常驻文字标签。
6. 悬停水平线显示中心价；悬停趋势线显示当前 K 线的拟合价和日期/时间。
7. 手动线常驻标签、删除、删除后重现虚线、切换周期及 K 线缩放均无回归。
8. 后端全量测试、静态检查、前端全量测试、生产构建和浏览器端到端验证全部通过。
